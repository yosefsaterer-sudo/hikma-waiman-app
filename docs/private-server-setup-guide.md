# إنشاء خادم خاص لـ «مراسل آمن»

## النتيجة المطلوبة

الخادم الخاص يتيح مزامنة المحادثات والملفات بين الأجهزة بدل وضع الزائر المحلي. التطبيق الحالي لا يحتاج خادمًا للتجربة كزائر، لكنه عند الربط يتوقع HTTPS للواجهات وWSS للتحديثات الفورية، ورمز دخول بصيغة `Bearer`.

> لا تبدأ بالمكالمات أو خادم TURN الآن؛ الإصدار الحالي يركّز على الرسائل والوسائط. يضاف TURN لاحقًا فقط عند إعادة تفعيل المكالمات.

## اختيار الاستضافة

| المسار | مناسب لـ | ما تحصل عليه | مستوى الإعداد |
|---|---|---|---|
| استضافة مُدارة مرتبطة بالمشروع | بداية صغيرة أو فريق محدود | خادم Node.js، قاعدة بيانات، تخزين ملفات، نطاق HTTPS | أبسط |
| خادم VPS مستقل مع Docker | سيادة كاملة أو عدد مستخدمين أكبر | API وPostgreSQL وRedis وتخزين ملفات وعكس HTTPS تحت إدارتك | أعلى |

الخيار الأول مناسب كبداية لأنك تدير إعدادات أقل. الخيار الثاني هو الأنسب إن أردت خادمًا مستقلًا تمامًا عن منصة التطبيق. في الحالتين يلزم نطاق مثل `msg.example.com` يشير إلى الخادم.

## مكونات الخادم

| المكوّن | الغرض |
|---|---|
| API Node.js (Fastify أو Express) | المصادقة، المحادثات، الرسائل، رفع الملفات |
| PostgreSQL | المستخدمون والمحادثات والرسائل وحالة القراءة |
| تخزين كائنات أو قرص منظم | الصور والفيديو والملفات؛ تحفظ قاعدة البيانات الرابط والبيانات الوصفية فقط |
| WebSocket | وصول أحداث `message.created` و`message.read` فورًا |
| Caddy أو Nginx | HTTPS وWSS أمام API؛ Caddy يصدر ويجدد الشهادات تلقائيًا عند ضبط DNS والمنافذ 80 و443.[1] |

## الواجهات التي يجب تنفيذها

نفّذ أولًا هذه المسارات المتوافقة مع التطبيق:

```text
GET  /health                         -> { "status": "ok" }
GET  /v1/conversations
GET  /v1/conversations/:id/messages?cursor=
POST /v1/conversations/:id/messages  -> { text, mediaIds }
POST /v1/media                       -> multipart/form-data (file)
WSS  /v1/realtime?access_token=...
```

ضع رمزًا قصير العمر في `Authorization: Bearer <token>` للـ REST، وصدّق الرمز أيضًا عند فتح WebSocket. استخدم HTTPS/WSS فقط في الإنتاج، وحدد حجم الرفع، وطبّق تحديد المعدل، وتجزئة كلمات المرور، ونسخة احتياطية يومية لقاعدة البيانات والملفات.

## خطوات التشغيل

1. أنشئ نطاقًا فرعيًا: `msg.example.com`، ثم أضف سجل DNS من نوع A إلى عنوان خادمك.
2. شغّل API وقاعدة البيانات والتخزين في حاويات منفصلة. توصي وثائق Docker بملف إنتاج منفصل وسياسة إعادة تشغيل لتقليل الانقطاع.[2]
3. ضع Caddy أمام API، وافتح 80 و443 فقط للخدمة العامة. بعد ضبط DNS يصدر Caddy شهادة HTTPS ويجددها تلقائيًا.[1]
4. نفّذ `/health` أولًا، ثم المحادثات والرسائل، ثم رفع الوسائط، ثم WebSocket.
5. في التطبيق افتح **الإعدادات ← الخادم الخاص** وأدخل `https://msg.example.com`، واترك المسارات الافتراضية كما هي، وأدخل رمز الوصول ثم اضغط **اختبار الاتصال**.

## المكالمات لاحقًا

عند إعادة تفعيل المكالمات، أضف `GET /v1/calls/ice` وخادم TURN منفصل. مشروع coturn هو تطبيق TURN/STUN مفتوح المصدر ويدعم تشغيله بالحاويات.[3]

## قرار البداية

ابدأ بخادم الرسائل والملفات فقط. بعد نجاح الاختبار بين جهازين نضيف مزامنة القراءة والإشعارات، ثم — إذا احتجتها — المكالمات وTURN.
